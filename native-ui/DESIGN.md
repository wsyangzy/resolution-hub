# 原生双布局、内容自适应浮层与新增流程

本阶段修正 Slint 控件默认几何导致的标题重叠、按钮越界与多余留白，并完善浅色组件层次。
提供工作条和应用窗口两种可切换布局、真实本地图标以及按内容决定高度的浮层，
保留与原版 ProfileEditor 对齐的新增游戏流程。
不迁移已有配置编辑、删除、显示设置、托盘或其他偏好；布局偏好单独保存。

## 主界面

- 工作条为 688×56 逻辑像素，放置拖动手柄、游戏图标与目标模式、启动/恢复、分组工具、
  布局入口和窗口控制。默认在工作区上方居中，所有内容点击展开。
- 应用窗口初始宽 860px，高度按列表在 320～680px 内确定，常规最小尺寸 660×320px，
  受工作区限制时进一步夹紧。使用自绘标题栏、同一套工具、常驻游戏库和紧凑状态栏；
  支持拖动、自由缩放、最大化/还原和双击标题栏。普通缩放事件不会重设默认尺寸。
- 两种布局由“布局”面板选择。切换不创建会话、不改变选择或恢复点；草稿与关闭确认期间禁止切换。
  应用窗口中的游戏选择入口聚焦常驻列表，不再展开另一份游戏库。
- EXE 采用 Windows GUI 子系统，双击启动时不产生额外的控制台窗口。
- 游戏库、详情、状态、新增和确认使用另一个顶层 Slint Window。两个 AppWindow 共享一份
  AppState、Controller 和 RuntimeManager，不创建第二个游戏会话。
- Slint 1.17 的 winit 后端将普通 PopupWindow 放在宿主内，无法承载工具条之外的功能内容。
  因此采用真实独立窗口，并用 Windows owner 关系保持浮层跟随主窗口最小化，不增加任务栏入口。
- 游戏库浮层宽 460px，高度随项目数变化，最多直接显示七项，其余内部滚动。每项高 52px，
  图标与名称在前、分辨率与刷新率在下。点击或 Enter 确认后收起工作条的列表，
  方向键/Home/End 在面板内选择，行尾和工具条的 ⓘ 打开详情。
- 详情与会话状态共用一个浮层；工具条只保留有状态圆点的统一入口，列表行尾仍可打开详情。
  头部显示图标、名称、目标模式、刷新与关闭，正文先展示状态与显示器，再显示配置字段。
  空闲不重复“就绪”，需要恢复时才显示固定底部操作。没有游戏配置时仍保留会话与恢复信息。
  配置字段使用左侧标签、右侧值，长路径换行。
  包含启动来源、游戏主进程、启动器类型/复用进程、显示器、切换时机、等待上限和恢复
  延迟；参数与工作目录按需显示。游戏选择沿用配置 ID，会话期间只允许查看当前游戏详情。
- 状态入口始终保留有色圆点；错误与异常恢复的完整文字在合并后的详情面板内查看。需要恢复时，
  工具条主按钮切换为“结束/恢复”，不会因收起面板而失去恢复入口。
- 延续浅色主题、轻边框和系统窗口阴影。PanelHeader 统一用布局分配标题与按钮宽度；
  工具条、标题栏、各面板头部和表单操作行显式设置 `cross-axis-alignment: center`，
  避免 HorizontalLayout 默认 stretch 将固定高度按钮贴在顶部。
  固定高度的滚动内容明确从 `(0, 0)` 开始，绝对定位按钮明确尺寸。
- 基础控件沿用 Slint 架构，参考官方 Fluent Button 的尺寸、禁用/按压/悬停分层与内部焦点描边，
  将共用交互收敛到 ActionArea，焦点视觉收敛到 FocusRing，不新增组件库依赖或引用私有 Fluent 实现。
  普通按钮与表单控件高 36px、紧凑按钮高 32px、圆角 6px；图标和文字由布局居中。
  选中状态使用浅色底和勾选，常态边框为中性色。鼠标和程序初始设焦不显示蓝框；
  Tab 导航显示一条内部 2px 焦点描边，确认窗口内的手动 Tab 循环仍显示焦点。
  Space/Enter 松开时激活一次，失焦或禁用时清除按压状态。
- 库、详情、状态、编辑器、布局与确认分别导出内容高度，窗口适配读取排版后的高度。
  工作条浮层优先向下，底部空间不足时向上；应用窗口的浮层在主窗口上居中。
  所有面板按工作区和 DPI 夹紧，大表单内部滚动，底部操作固定，不强行铺满屏幕。
- Motion 统一控制反馈 120ms、按压 65ms、展开 180ms、收起 100ms。
  独立浮层在目标尺寸的透明起点实际绘制后进入，切换内容也重置起点；淡入配合 8px 轻移，
  工作条上方展开时反转方向。系统禁用动画则同步显示，不等待进入计时。
  展开和收起回调共用代次保护，迟到回调不能隐藏或改写已经重开的浮层；不逐帧调用原生几何 API。
  高级区改变内容高度并淡入，避免每一帧都触发原生窗口缩放；Rust 隐藏计时读取同一退场时长。
  Windows 关闭动画效果时全部归零。弹窗退场结束前继续阻止背景输入。
- 共用纯图标按钮按视觉层中心直接定位，不用空文字控件测量宽度；程序设焦显式清除键盘
  焦点标记，鼠标悬停/按压不引入额外描边，Tab 导航保留内部焦点描边。
- 同一工具按钮可切换展开/收起，关闭浮层和 Escape 只处理面板。仅当工具条与浮层均失焦，
  才收起浏览类面板，延迟确认焦点可避免点击工具条时重复展开。新增与确认保持显示，以支持
  切到启动器登录和选择文件。所有操作保留可见焦点和辅助功能标签。

## 图标、偏好与性能

- 复用共享 `icon::load`，保持原版提取优先级。请求按 LaunchType 只传当前来源字段，保留主进程名，
  排除其他来源残留的路径。先读快捷方式或显式 EXE；Steam 先查找主进程 EXE，提取失败再回退缓存。
  来源目录中尚未配置主进程的 Steam 条目仍直接使用缓存；已配置游戏的缓存键包含主进程，二者互不覆盖。
  独立后台队列提取和解码，支持 Windows 预乘 RGBA 与 PNG/JPEG，
  缩略到最长边 64px，并限制解码尺寸和内存。读取失败保留首字或通用标记，不影响启动。
  不通过清除黑色像素制作透明背景；原图中的透明、半透明和真实黑色内容均保留。
- 图标请求按 Windows 路径大小写去重，成功和失败都缓存。Slint Image 留在 UI 线程；
  可见行和当前选择按需请求，完成后只更新匹配的模型行与当前游戏图标，不整页重新渲染。
- 游戏库只创建可见行及两行缓冲。Steam/最近来源和候选进程列表通过 Slint 原生 ListView
  虚拟化保留视口中的行，避免 `first-row + slot` 在跨行时使整组数据、图标和文字布局失效。
  本地 ListView 适配器使用 Slint 1.17 支持的五个属性，继续复用 VScroll 和固定轨道预留；
  升级时核对生成代码仍调用 `ensure_updated_listview`。来源行维持 48px 步长与 46px 卡片，
  内部使用固定几何和文本省略，悬停/按下/选择即时反馈，不在滚动中追加行颜色动画。
  列表索引只用于定位，来源选择始终回传原目录的 `entry.index`。
- 主窗口不绑定隐藏编辑器模型；目录修订号、来源、搜索和选择变化才重建来源列表，
  目录或显示器变化才重建显示模式。新表单打开前使旧缓存失效。
- 主窗口几何与面板内容高度变化合并到一次 16ms 更新；忽略浮层自己定位产生的普通几何事件。
  先按物理像素确定宽度，再测量文本高度，防止非整数 DPI 下反复改变换行。
- `%APPDATA%\resolution-hub\native-ui-settings.json` 保存 `viewMode`，支持 `toolbar` / `window`，
  不存在或缺失字段时默认工作条，损坏时给出提示。单一后台写入者按点击顺序保存并替换临时文件。
  不改共用 `settings.json`、GameProfile 或 Tauri command 契约，不持久化窗口尺寸和位置。

## 原版新增流程对应关系

权威参照为 `frontend/src/components/ProfileEditor.tsx` 及 `ProfileEditor.test.tsx`。

| 原版步骤 | Slint 实现 |
| --- | --- |
| 01 启动来源与进程 | 同样提供 Steam、启动器、本地 EXE、最近运行，默认 Steam |
| Steam 库 | 名称/App ID 搜索、刷新、来源选择；高级设置保留手填 App ID |
| 启动器类型 | 无畏契约与其他启动器分别选择 .lnk/.url |
| 无畏契约预设 | 名称“无畏契约”、Riot Client、VALORANT-Win64-Shipping.exe、10 分钟等待 |
| 最近运行 | 复用 recent::list 的历史与当前可见应用，按 EXE 类型保存 |
| 主进程识别 | EXE/Steam 启动并识别；启动器先打开，用户完成登录更新后再开始识别 |
| 候选处理 | 一个候选自动填写，多个候选显示进程名、路径与 PID 供选择 |
| 02 显示模式与恢复 | 目标显示器、受支持的分辨率/刷新率、退出后恢复延迟 |
| 03 高级启动设置 | 默认折叠；按来源显示路径、参数/工作目录、启动器复用进程、切换时机、等待上限 |
| 保存 | 校验与时间换算后复用 profile::save；成功收起面板并在工具条选中新游戏，失败保留草稿 |

普通启动器快捷方式不推断游戏主进程；更换具体游戏来源时清除旧识别结果，避免沿用前一个游戏。
等待默认 10 分钟、范围 1～60 分钟，保存为秒；恢复延迟默认 2 秒、范围 0～30 秒，保存为毫秒。
EXE / 最近运行默认启动前切换，Steam / 启动器默认检测到游戏进程后切换。
已发布的 GameProfile JSON 字段不变，新表单的来源类别仅用于 UI，不新增持久化枚举。

## 线程、取消与恢复

- 来源枚举、文件选择、打开启动器、识别和保存均在后台执行，不阻塞 Slint 事件循环。
- 共享后端公开 detector、launcher、recent，原生入口复用同一份启动器复用判断、Steam 库、
  最近应用历史和识别规则。Tauri command 和 React 调用边界不变。
- 原版 detector::detect 保留原签名，内部委托支持取消的 detect_with_cancel。轮询前、
  启动前、收集候选和返回前均检查取消。EXE/Steam 仍为 60 秒，启动器仍为 120 秒。
- 原生识别操作使用独立 generation 和取消标记；取消后先等待 worker 返回，再恢复表单操作。
  迟到回调不覆盖输入，也不改变下一次操作。取消不会终止游戏或启动器。
- 最近应用过滤同时排除 Tauri 与 Slint 可执行文件；打开新增表单和刷新最近来源仍按原版写入
  recent-apps.json。单元测试不触发此流程。
- 识别只打开启动来源并观察进程，不创建游戏会话、不切换显示模式。保存前重新确认显示器模式
  仍然可用，之后才写入游戏配置。
- 识别期间关闭应用会先发出取消，等后台完成后才允许确认退出。文件选择和保存仍须等待操作
  完成；有未保存输入时先确认。真正退出继续经过既有的恢复检查，失败保留窗口和恢复点。
- 主工具条关闭与系统关闭走原安全退出；浮层关闭不退出应用。识别期间关闭浮层先取消识别并
  保留表单；选择文件、打开启动器、保存期间不收起表单。丢弃确认与退出确认优先于普通面板。
- 未改动显示切换、恢复目标选择、单游戏会话和持久化模式切换逻辑。

## 交互与后台性能

- 运行状态锁与恢复文件读取通过独立按请求线程完成，空闲时阻塞等待；状态事件合并并用修订号
  拒绝过期快照，恢复错误仍按原安全约束处理，不用缓存值替代启动/关闭前的读取。
- 表单输入、搜索和来源选择只同步编辑器；隐藏浮层不绑定整套属性，模型未变不重复赋值。
- 图标模型建立 ID 到行号索引，异步完成只访问匹配行，替换模型即替换索引，不保留旧目录更新目标。
- 浮层进入前，目标逻辑尺寸、Slint 窗口几何、渲染表面与 Windows 客户区尺寸必须一致；
  仅尺寸匹配的绘制完成通知可提交进入状态。排队回调同时核对面板代次、内容和物理尺寸，
  切换面板或调整尺寸后的旧帧不能放行。关闭系统动画也保留尺寸检查。
  内容与边框按目标尺寸绑定，尺寸事件未到达前隐藏表面，避免旧大窗口的边框参与淡入。
  首次映射和重新显示窗口前先等待尺寸就绪；准备期间按 16ms 间隔做有上限的检查，
  窗口显示后由绘制通知接续，不在空闲状态持续检查。
  无绘制通知时才使用有上限的 16ms 计时回退，关闭或再次打开会使旧回调失效。
- 开发构建仅给原生 UI 包启用一级优化，保留调试符号，不改变共享后端监控频率或显示恢复语义。
- 性能日志默认关闭，显式开启后用有界队列写入后台日志；帧间隔、点击延迟、CPU 提交耗时分别记录，
  不以渲染通知代替 GPU/DWM 呈现数据。手动采样脚本记录进程 CPU/内存并支持无动画对照。
  实际测量与判读方式见 README 的“流畅度与后台性能采样”，不由开发工具启动窗口执行视觉验收。

## 验证与交付

非视觉检查：cargo fmt --check、原生包 cargo check、状态/编辑器/定位/图标/偏好测试。
按钮与图标修正只作用于原生 UI；共享图标提取、detector、recent 和显示切换逻辑保持原状。
交付 Debug EXE 时实际链接，
检查 Windows GUI 子系统与内嵌 Common-Controls v6 清单。非视觉检查不能证明窗口布局、图标外观、真实流畅度或添加成功。

用户自行检查：688×56 工作条与应用窗口的切换/重启记忆、普通窗口缩放/最大化后切回、
标题与按钮位置、图标、自适应高度、输入和滚动流畅度、点击展开/收起、独立浮层不扩大宿主、
屏幕边缘定位、多显示器/DPI、最小化联动、长游戏名、键盘导航与 Windows 动画开关；随后验证四类来源、
两种启动器预设、两阶段识别、单/多候选、取消识别、保存失败、未保存退出和重启后配置保留。
不由开发工具启动窗口、浏览器、预览服务或游戏，不代替用户执行真实显示模式切换。
