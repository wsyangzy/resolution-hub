# Slint 原生界面：工作条与应用窗口

本阶段复用现有 Rust 运行时，支持添加游戏配置、选择游戏、启动与守候、结束会话、
恢复桌面和安全退出，并提供可记忆的布局选择。已有配置编辑、显示设置、托盘和其他应用偏好留待后续阶段。

## 界面与窗口

点击工具条的“布局”可在两种浅色界面之间切换；切换保留当前游戏、会话和恢复状态。

| 布局 | 主窗口 | 功能展开方式 |
| --- | --- | --- |
| 工作条（默认） | **688×56 逻辑像素**，左侧拖动，右侧最小化与安全关闭 | 游戏库、游戏与会话详情、添加和布局选择均点击展开 |
| 应用窗口 | 初始宽 860px，高度按列表内容在 320～680px 内确定；支持缩放、最大化与还原 | 游戏库常驻，详情、状态与添加使用浮层 |

应用窗口的常规最小尺寸为 660×320px。两种模式都按当前显示器工作区夹紧尺寸和位置；
工作条默认位于工作区上方居中，应用窗口默认居中。应用窗口使用自绘标题栏，右上角提供
最小化、最大化/还原和关闭，双击标题栏可最大化。EXE 使用 Windows GUI 子系统，不附带控制台。

布局选择单独保存到 `%APPDATA%\resolution-hub\native-ui-settings.json`，默认 `viewMode: "toolbar"`，
窗口模式为 `"window"`，不修改共用的 `settings.json`。后台按选择顺序保存；保存失败会在布局面板提示。
此阶段只记住布局，不持久化窗口尺寸和位置。新增或关闭确认期间不允许切换布局。

工作条点击游戏区域展开游戏库；应用窗口点击同一区域聚焦常驻列表。每项高 52px，名称在上、
分辨率和刷新率在下；点击游戏或按 Enter 确认选择，工作条的列表随后收起。
方向键与 Home/End 可在列表中选择。行尾 ⓘ 和工具条状态按钮打开同一份游戏与会话详情，
启动来源、主进程、启动器进程、显示器、切换时机、等待上限与恢复延迟在详情中查看。
详情顶部集中显示状态与显示器，下面采用左侧字段名、右侧内容的紧凑排版，长路径按可用宽度换行。
空闲时不重复显示“就绪”，刷新移至头部；仅需要结束会话或恢复桌面时显示固定底部操作。
工具条合并重复的详情/状态按钮，仍可在没有游戏配置时通过状态入口查看并恢复异常桌面模式。

工具条、游戏库、详情及新增来源列表显示本地图标。图标请求按当前启动类型选择路径，与原版一致：
先读取快捷方式或显式 EXE；Steam 游戏先按主进程查找游戏 EXE，失败后才回退本地缓存，
保留 EXE 图标的透明通道。没有配置主进程的 Steam 来源条目仍可使用缓存图；不从网络下载素材。
图标在后台提取和解码，进入可视范围后加载，
成功和失败均缓存；无法读取时使用名称首字或通用标记。不会为获取图标启动游戏。

各功能使用独立的 Windows 浮层，展开时主工具条仍保持原尺寸。游戏库高度随项目数变化，
最多直接显示七项，其余滚动查看；游戏与会话详情、添加与确认面板按实际内容计算高度。
合并后的详情保留完整的会话、错误与桌面恢复信息。
浮层跟随工具条，底部空间不足时向上展开，按所在显示器工作区与 DPI 限制尺寸。
应用窗口模式的浮层在主窗口上居中，使用整个工作区限制尺寸。
内容过长时内部滚动，保存、取消和恢复操作固定在底部。浮层属于主窗口，
不增加任务栏入口，随主窗口最小化隐藏。

再次点击对应工具按钮、点击浮层关闭或按 Escape 可收起。浏览类面板在两个窗口均失焦后
收起；新增表单与确认窗口不会因切到启动器、文件选择器或其他应用而收起。关闭浮层只处理
该面板，关闭主窗口才走完整安全退出；有草稿、识别或保存操作时仍按原有保护处理。

控件保持浅色样式、系统窗口阴影，以及悬停、按压、选中、键盘焦点与展开/收起反馈。
基础组件参考 Slint 官方 Fluent Button 的固定尺寸与状态规则，统一使用 `ActionArea` 和
`FocusRing`，没有新增第三方组件依赖。普通按钮/输入控件高 36px、紧凑按钮高 32px，圆角为 6px；
工具条、标题栏、面板头部和表单操作行显式垂直居中。布局选项以浅蓝底和勾选表示选中，常态边框为中性色。
鼠标点击和面板初始设焦不显示蓝框；Tab 导航使用一条控件内的 2px 描边，Space/Enter 松开时激活一次。
关闭 Windows“动画效果”后过渡立即完成。按压不改变命中区域，确认窗口退场时仍拦截背景。
反馈、按压、展开和收起分别为 120 / 65 / 180 / 100ms。面板标题与操作统一由布局分配位置，
绝对定位按钮明确指定宽度；滚动内容固定从顶部开始，不依赖 Slint 的默认居中行为。
所有独立浮层先提交透明起点，确认窗口与目标尺寸一致后再淡入并移动 8px；从工作条上方展开时反转进入方向，
切换面板也重新播放进入动效。动画只影响绘制，不逐帧调整原生窗口尺寸或位置。
收起计时与展开共用代次保护，快速关闭再打开时旧回调不能隐藏新面板；关闭系统动画时直接显示。
纯图标按钮独立居中，不让空文字控件参与几何计算；程序设焦显式清除键盘焦点标记，Tab 仍显示描边。

游戏库只创建可见行及两行缓冲；Steam、最近应用和候选进程列表使用 Slint 原生列表虚拟化，
保留仍在视口中的行，仅为新进入视口的项目创建行。界面缓存来源目录、显示模式和游戏模型；
普通表单输入不重建这些列表，主窗口也不更新隐藏表单。图标完成后只更新对应行。
窗口几何更新在 16ms 内合并，浮层自身的移动/缩放事件不会反向触发主窗口重定位。
这些是减少重复工作的实现措施，尚未进行真实窗口的流畅度测量。

- `ui/theme.slint`：浅色配色与统一动效参数。
- `ui/workbar.slint`：常驻工具条、游戏选择入口与分组操作按钮。
- `ui/components.slint`：按钮、游戏列表、滚动、状态与关闭确认。
- `ui/panels.slint`：共用游戏库、紧凑会话摘要和布局选择面板。
- `ui/source-list.slint`：Steam、最近应用和候选进程共用的可滚动选择列表。
- `ui/game-details.slint`：按需打开的游戏与会话详情，含恢复操作。
- `ui/form-controls.slint`、`ui/game-editor.slint` 与 `src/editor.rs`：新增表单、来源处理、
  进程识别步骤、草稿校验和保存。
- `ui/chrome.slint` 与 `src/chrome.rs`：自绘标题栏、拖动手柄、Windows 所属窗口关系和 DPI/工作区适配。
- `src/placement.rs`：按物理像素计算浮层位置与可用尺寸。
- `src/icons.rs`：后台图标队列、解码、缓存和定向更新。
- `src/presentation.rs`：UI 线程上的列表与显示模式模型缓存。
- `src/runtime_reader.rs`：按请求读取运行与恢复状态的后台线程，合并通知并拒绝过期结果。
- `src/performance.rs`：默认关闭的操作耗时与绘制采样，带有界队列和日志大小限制。
- `src/preferences.rs`：独立布局偏好的读取、兼容默认值和串行保存。
- `ui/app-window.slint` 与 `src/state.rs`：双窗口内容组合、面板切换、操作互斥和安全关闭。

设计范围与验收约定见 [DESIGN.md](DESIGN.md)。winit 接口与版本相关，因此 Slint
保持在 1.17 的补丁版本范围；后续升级小版本时需要重新检查窗口接口。

## 添加游戏与查看详情

操作顺序对照 `frontend/src/components/ProfileEditor.tsx` 与其测试，分为启动来源与进程、
显示模式与恢复、高级启动设置三部分。

1. 点击工具条“+”或游戏库中的“添加”。默认进入 Steam，来源顺序为 Steam、启动器、本地 EXE、最近运行。
2. 选择来源：
   - Steam：搜索并选择已安装游戏，支持刷新；高级设置保留手填 App ID。
   - 启动器：选择“无畏契约”或“其他启动器”，再选择 `.lnk` / `.url` 快捷方式。
     无畏契约预填 `Riot Client`、`VALORANT-Win64-Shipping.exe` 和 10 分钟等待时间。
     其他启动器需要填写或识别实际游戏主进程。
   - 本地 EXE：选择文件，自动填写游戏名称和进程。高级设置中重新浏览 EXE 时保留自定义名称。
   - 最近运行：刷新并选择最近出现过窗口的应用，按 EXE 来源保存路径和主进程。
3. 确认游戏名称与主进程。Steam / EXE 使用“启动并识别”；启动器分两步：先“打开启动器”，
   完成登录或更新后点击“开始识别”，再从启动器进入游戏。只发现一个候选时自动填写，
   多个候选时由用户选择。识别不会切换分辨率，EXE / Steam 超时 60 秒，启动器超时 120 秒；
   可点击“取消识别”或按 Escape 停止等待，已打开的应用继续运行。
4. 选择显示器、分辨率与刷新率，并设置退出后恢复延迟。高级启动设置默认折叠，包含启动路径、
   EXE 参数/工作目录、启动器复用进程、切换时机和等待上限。
5. 点击“保存配置”，收起表单并在工具条选中新游戏。保存前重新确认显示模式仍受支持；失败保留草稿。
   取消有修改的表单或关闭应用时先确认。

默认等待 10 分钟（范围 1～60 分钟），恢复延迟 2 秒（范围 0～30 秒），保存时分别转换为秒
和毫秒。EXE / 最近运行默认启动前切换，Steam / 启动器默认检测到游戏主进程后切换。
保存只创建配置；从工具条“启动”开始显示模式会话。

启动器仍复用共享的 `launcher::launch_request`，确认已在运行时不重复打开。配置的启动器进程
用于启动器复用，游戏主进程用于游戏启动/退出判断。切换来源或快捷方式会使旧识别状态失效，
取消后的结果不会覆盖草稿。

新增配置与 Tauri 共用 `profiles.json`。打开新增表单或刷新“最近运行”时，沿用原版
`recent::list` 刷新 `recent-apps.json`；测试使用内存数据，不调用这些实际读取/写入流程。

## 行为约定

- 游戏选择按配置 ID 保存。刷新配置时保留仍存在的选择；配置被删除时选择第一项，
  空列表不允许启动。会话和后台操作期间不能切换游戏或刷新配置。
- 启动前读取异常恢复点。存在恢复点或无法读取恢复点时，显示恢复提示并禁止启动；
  游戏配置或显示器读取失败不能遮住恢复操作。
- 游戏退出后由现有运行时恢复桌面并继续守候。即使守候时没有恢复点，仍属于活动
  会话，需要通过“结束会话”停止监控。
- “结束会话”和“立即恢复”复用 `restore_now_with_sink`。恢复在后台线程执行，
  同一时间只允许一项界面发起的后台操作；不终止游戏进程。
- 关闭活动会话、存在恢复点或尚未完成的操作时先确认。启动操作尚未返回时不能
  开始关闭恢复；操作完成后可继续确认。返回或 Escape 只取消关闭确认。
- 确认退出后先恢复。只有恢复调用成功、恢复点确认已清除且会话结束，才退出
  事件循环。恢复失败保留窗口、错误信息和重试入口。
- 运行时事件到达界面时重新读取当前状态，避免排队中的旧事件覆盖恢复后的界面。
  事件循环异常结束时，再使旧 worker 失效并尝试恢复；失败仍保留恢复点。

## 本地运行

Shell 使用 PowerShell，工作目录为仓库根目录。需要现有 Rust/MSVC 构建环境。
先退出 Tauri 版本并确认桌面已经恢复；两个程序共用 `%APPDATA%\resolution-hub`
下的数据和恢复点，不应同时操作显示模式。

```powershell
cargo run -p resolution-hub-native-ui --locked
```

这是启动原生窗口的手动命令。可直接在原生版添加游戏；修改已有配置时仍使用 Tauri
版本的配置编辑器，退出后再打开原生版并刷新列表。启动游戏会沿用现有
使用次数记录和显示恢复点机制，不迁移或重写已有游戏配置。

已经完成 Debug 构建时，也可以直接运行生成的程序，不需要重复编译：

```powershell
& .\target\debug\resolution-hub-native-ui.exe
```

返回 Tauri 版本时，先在原生界面结束会话并正常退出，再从仓库根目录运行
`npm run dev`。恢复失败时应保留 `pending-restore.json` 并重试恢复。

## 非视觉检查

以下命令在仓库根目录执行，不启动游戏或应用窗口：

```powershell
cargo fmt --check
cargo check -p resolution-hub-native-ui --locked
cargo test -p resolution-hub-native-ui --locked
```

只改原生界面时检查原生包；改动共享后端时再按范围扩大检查。涉及窗口 API、构建脚本
或 Windows 链接配置时，还需构建实际的原生 EXE：

```powershell
cargo build -p resolution-hub-native-ui --locked
```

原生工程的 `build.rs` 会用 MSVC 链接参数嵌入 Common-Controls v6 应用清单。
复用后端带入的 `muda` 依赖会导入 `TaskDialogIndirect`；缺少该清单时，程序可能
在进入 `main` 前就报“无法找到入口”。依赖库中的 Tauri 清单不会自动传给独立 EXE，
因此不能仅用 `cargo check` 或会话单元测试代替最终可执行文件的清单检查。

`src/state.rs`、`src/editor.rs` 与 `src/placement.rs` 的测试使用内存数据，覆盖选择保持、
面板收起与关闭保护、恢复限制、来源与草稿、保存失败、屏幕边缘定位及 DPI 间距计算，
不修改真实用户配置或显示模式。
图标测试使用内存像素和 PNG，覆盖来源隔离、主进程保留、透明度、去重及解码；
偏好测试只在独立临时目录验证默认值、替换和错误处理，随后清理。
类型检查也会编译 Slint 界面定义。上述检查不能代替真实窗口和硬件验收。

## 添加游戏时的来源列表滚动

来源列表原先使用 `first-row + slot` 复用固定数量的控件。每跨过一行，所有槽位的模型索引
都会改变，连带使整组文字、图标和嵌套布局失效；行悬停和选择的颜色过渡还会延续额外绘制。
这说明滚动路径存在重复工作，不能单凭源码判断它占实际掉帧的比例。

现在由 Slint 1.17 的原生 ListView 重复器保留视口内的行，滚动偏移不再参与每行的数据绑定。
本地 `ListView` 适配器暴露框架识别所需的五个属性，并复用现有 VScroll、12px 轨道预留和滚轮行为；
升级 Slint 时需复查生成代码中的 `ensure_updated_listview`，避免退化成创建全部条目的普通重复器。
每行仍占 48px，卡片高 46px；图标、两行文字和右侧信息改为显式尺寸，减少布局求解。
行悬停、按下、选中和键盘描边即时反馈，滚动位移继续使用 Flickable 的平滑滚动。
搜索/切换来源仍回到顶部；点击和 Enter/Space 继续传递原目录的 `entry.index`，
方向键、Home/End、空列表、禁用状态与多候选流程保持原有契约。

```powershell
& .\native-ui\scripts\Measure-Performance.ps1 -DisableAnimations
```

输出目录默认位于系统临时目录，内含 `performance.jsonl` 与 `process.csv`。
日志只记录固定操作名、时间、窗口角色、显示器刷新率/缩放和性能数值，不记录游戏名、输入内容或文件路径。
诊断队列最多 256 条，拥塞时丢记录并累计 `droppedRecords`；单次 JSONL 最多 8 MiB，写盘只在日志线程执行。
诊断默认关闭，不设置环境变量时没有日志文件、诊断写入线程或进程采样循环。

可单独汇总已有日志：

```powershell
& .\native-ui\scripts\Summarize-Performance.ps1 -Path '日志目录\performance.jsonl'
```

| 指标 | 含义与判断边界 |
| --- | --- |
| `ui-render` / `editor-render` | Rust 同步 UI 属性的耗时，不包含 GPU 呈现；高值指向 UI 更新开销 |
| `window-layout` / `panel-sync` | 窗口约束、内容测量与面板同步耗时 |
| `runtime-read` / `runtime-round-trip` | 后台实际读取与排队到 UI 完成的时间；后者包含调度与后续回调 |
| `render-cpu` | 绘制通知之间的 CPU 提交段，不含之后的缓冲交换/GPU/DWM 显示延迟 |
| `input-to-render` | 当前窗口收到输入到下一次开始绘制，不是功能操作完成时间或跨窗口首屏延迟 |
| `animation-interval` | 连续采样点均在浮层展开/收起动效中的绘制间隔；不把静止窗口当低 FPS |
| `monitor-frame-budget` | 当前窗口所在显示器刷新周期，60Hz 约 16.67ms，144Hz 约 6.94ms |
| `process.csv` | CPU 按系统逻辑处理器总数归一化；常驻内存、私有内存、句柄与线程按秒记录 |

汇总提供样本数、中位数、P95 与最大值。先比较同一机器、显示器、布局和操作顺序下的两组记录。
若无动画仍有较高的 UI 工作耗时，继续检查调用链；若工作耗时较低但动画间隔显著高于显示器周期，
需结合渲染/驱动/系统调度定位。超过 250ms 的间隔保留 `longGap` 标记，可能来自静置或阻塞，不能直接判为掉帧。
有丢记录或通知不可用时，汇总会明确提示采样不完整。两组进程数据可比较静置段及重复操作后的变化，
不能用一次进程的瞬时内存值证明泄漏或宣称长期后台性能达标。
