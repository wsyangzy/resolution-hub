# Slint 原生界面

`resolution-hub-native-ui` 是当前唯一应用入口，依赖独立的 `resolution-hub-core`。
Slint 使用 winit 与 femtovg，Windows EXE 内嵌图标、版本资源和 Common-Controls v6 清单，
采用 GUI 子系统。运行不需要 React、Tauri 或 WebView2。

## 布局与操作

默认工作条为 688×56 逻辑像素，游戏库、详情、状态、添加、布局和确认在独立浮层中展开。
应用窗口初始宽 860px，按内容确定高度，可自由缩放和最大化；常规最小尺寸为 660×320px，
受工作区限制时进一步夹紧。布局选择保存在 `native-ui-settings.json`，不保存窗口尺寸和位置。

主窗口和浮层共享 AppState、Controller 与 RuntimeManager，不创建第二个会话。
浮层通过 Windows owner 关系跟随最小化，不增加任务栏入口。浏览面板在两窗口都失焦时收起，
添加和确认面板在切换至启动器或文件选择器时保留。

## 新增流程

| 来源 | 操作 |
| --- | --- |
| Steam | 扫描本机库、按名称或 App ID 搜索，也可在高级设置手填 App ID |
| 启动器 | 无畏契约预设或其他启动器，选择 `.lnk` / `.url` 后先登录更新，再识别游戏主进程 |
| 本地 EXE | 选择程序，自动填写名称和主进程，可启动并识别 |
| 最近运行 | 刷新本机最近活动来源，选中后按 EXE 配置保存 |

一个进程候选自动填写，多个候选显示进程名、路径和 PID 供选择。
更换来源会清除旧识别结果，列表始终用来源目录原始索引回传选择。
等待默认 10 分钟、范围 1～60 分钟，保存为秒；恢复延迟默认 2 秒、范围 0～30 秒，保存为毫秒。
EXE/最近运行默认启动前切换，Steam/启动器默认检测到游戏主进程后切换。

来源枚举、文件选择、启动器打开、识别和保存都在后台执行。
识别有取消和代次保护，取消不会结束游戏或启动器。关闭时等待正在进行的文件选择、保存或取消完成，
草稿未保存时先确认，之后继续走会话恢复与安全退出。

现阶段提供新增和读取配置，尚未提供已有配置编辑/删除、桌面默认模式设置、托盘和开机自启入口。
旧 JSON 格式与默认模式继续兼容；关闭窗口按安全退出处理。

## 流畅度实现与验证边界

- Steam/最近来源和进程候选使用 Slint 原生 ListView 虚拟化，只实例化可见行。
  来源行步长 48px、卡片高 46px，固定几何并省略长文本；滚动时不追加行颜色动画。
- 来源、搜索、选择或目录修订变化才重建对应列表，隐藏编辑器不绑定主窗口模型。
- 图标在独立队列提取、解码和缩略；成功与失败均缓存，按 ID 索引仅更新对应模型行。
- 运行状态锁与恢复点读取由后台 Reader 串行处理，重复通知合并，过期结果按修订号丢弃。
- 几何更新合并到一次 16ms 调度；先确定物理像素宽度再测量内容，不逐帧调用原生窗口定位。
- 浮层先在目标尺寸完成透明起点绘制，再进入淡入和轻移动画；后端不支持绘制通知时采用有上限的计时回退。
- 日常没有持续 UI 刷新或恢复文件轮询，诊断默认关闭。以上属于实现说明，实际帧率、首次浮层边框和空闲性能仍由用户验收。

历史本地验证记录保存在迁移前提交 `1b670d5` 中；清理后的编译与测试以 GitHub Actions 结果为准。
不要用旧 EXE 的哈希或测试数量代表当前源码已通过验证。

## 用户手动性能采样

从 GitHub Actions 下载当前 EXE 后，可用以下 PowerShell 命令比较动画开启与关闭的表现。
工作目录为仓库根目录，先结束旧会话并正常退出已有实例。
`-Executable` 必须指向下载并解压的 EXE；脚本会启动应用，每秒记录 CPU、内存、句柄和线程数，
正常退出后汇总，不自动点击界面或启动游戏。

```powershell
& .\native-ui\scripts\Measure-Performance.ps1 -Executable 'C:\下载目录\resolution-hub-native-ui.exe'
& .\native-ui\scripts\Measure-Performance.ps1 -Executable 'C:\下载目录\resolution-hub-native-ui.exe' -DisableAnimations
```

每次按相同顺序打开游戏库、详情、布局与添加，搜索并滚动同一来源列表，再静置 30 秒并关闭。
脚本恢复原环境变量，默认在临时目录为每次采样新建子目录，生成 `performance.jsonl` 和 `process.csv`。
也可单独汇总已有日志：

```powershell
& .\native-ui\scripts\Summarize-Performance.ps1 -Path '日志目录\performance.jsonl'
```

| 指标 | 含义与限制 |
| --- | --- |
| `ui-render` / `editor-render` | Rust 同步 UI 属性耗时，不含 GPU 呈现 |
| `window-layout` / `panel-sync` | 窗口约束、测量和面板同步 |
| `runtime-read` / `runtime-round-trip` | 后台读取耗时 / 包含排队与回调的往返耗时 |
| `render-cpu` | 绘制通知之间的 CPU 提交段，不含 GPU/DWM 显示延迟 |
| `input-to-render` | 收到输入至当前窗口下一次开始绘制，不是功能完成时间 |
| `animation-interval` | 浮层展开/收起期间的绘制间隔，不代表来源列表滚动帧率 |
| `process.csv` | 按逻辑处理器数归一化的 CPU，以及内存、句柄、线程采样 |

日志仅包含固定操作名、窗口角色与性能值，不记录游戏名、输入内容或文件路径。
队列最多 256 条、JSONL 最多 8 MiB，拥塞丢弃记录并计数，不阻塞交互。
比较同机器、显示器、布局和操作顺序的样本，中位数/P95 和超过 250ms 的 longGap 都需结合使用场景解释。
存在丢记录或不支持绘制通知时，采样结果不完整。

## Windows 手动验收

由用户在工作条、应用窗口和浮层中检查：

- 首次打开、切换和快速重开浮层，检查边框、位置、淡入以及 Windows 动画禁用行为。
- Steam/最近来源的搜索、长列表滚动、点击、方向键、Home/End 和 Enter 选择。
- 四种新增来源、单个/多个候选、取消识别、保存失败重试和未保存关闭确认。
- 688×56 工作条、660×320 最小应用窗口、手动缩放、最大化、常见 DPI 与多显示器边缘。
- 游戏正常退出与再次启动、启动超时、取消等待、手动恢复、活动会话关闭和恢复失败重试。

CI 不启动界面、游戏或真实显示切换；自动检查通过不能代替这些验收。
